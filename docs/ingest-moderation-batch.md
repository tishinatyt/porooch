# Массовая модерация — 17.11.2026

## Диагностика пропусков

Повторно применить `docs/sql/ingest-moderation-batch.sql`. Читающий запрос `docs/sql/ingest-skip-diagnostics.sql` не зависит от новых функций: город задаётся в первом CTE `params(city)`. Он показывает старую/новую проверку места и дублей, дату в UTC/Киеве, статус, категорию, количество source aliases и pending-копий. Категория без пользовательской правки не ограничивается; версия клиента в режиме фильтра отсутствует. Изменение после начала операции проверяется отдельно.

Точную причину результата 2/23 без чтения продовых записей подтвердить нельзя. В проверенном коде нет разрешения только для кино; старый дубль исключал саму запись (`d.id<>...`), а UNIQUE dedup_hash уже объединяет одинаковые события из разделов в одну запись с несколькими source_keys. Эти aliases не являются основанием для отказа. Поэтому утверждать, что именно дедупликация отсеяла 23 события, было бы неверно.

Устранены ограничения проверки места: учитываются raw_data.location/venue/name/address, включая строковые значения; сборщик также понимает venue и строковый location. При публикации найденное альтернативное место сохраняется в place. Сравнение даты остаётся между timestamptz, без усечения до календарного дня; 20:00 Киева сегодня проходит до наступления этого времени.

Копия теперь отбрасывается только при наличии уже опубликованной канонической записи. Сравнение учитывает hash либо нормализованные название + город + место + точное время, не источник/раздел. Первая корректная pending-запись публикуется; следующие при обработке становятся rejected с raw_data.moderation_reason=duplicate и duplicate_of. Не выбранные копии остаются pending до своей обработки. Взаимной блокировки pending-копий нет.

RPC возвращает reasons и до 20 examples (id/title/reason), интерфейс суммирует причины по порциям и ограничивает общий список примеров двадцатью. Причины: date, title, venue, duplicate, category, version, changed_after_start, status, event_status, missing. Правки версий/статуса не обходятся. Для уже применённой миграции добавлена новая `20261117130000_moderation_skip_diagnostics.sql`; ручной SQL и обе миграции пакетной модерации идентичны.

Проверены парсер двух разделов, альтернативное место, вечерняя дата Киева, агрегация причин, ограничение примеров, статическая структура SQL. SQL на PostgreSQL не выполнялся по запрету подключения к базе.

Исправление ошибки 42702: локальные переменные имеют префикс `v_`; в UPDATE чтение колонки — `e.category`, переменной — `v_category`. Исправленный SQL можно выполнять повторно (`create or replace`). Добавлена идентичная миграция `20261117120000_ingest_moderation_batch.sql`. Обе старые перегрузки `poruch_ingest_moderate` сохранены для совместимости; пакетный RPC их не вызывает. Связанные SQL-обёртки категории используют явные типы аргументов. В интерфейсе исходный `message` базы показан под общим сообщением, включая ошибки последующих порций.

SQL для ручного применения: [sql/ingest-moderation-batch.sql](sql/ingest-moderation-batch.sql), после существующих event-source-scaling и ingested-event-category. Новый RPC доступен только администраторам; чужие таблицы не затрагиваются. SQL не применялся, подключений к базе не было.

Выбранные записи обрабатываются независимо: изменившиеся версии, удалённые записи и непригодные события пропускаются. Публикация проверяет будущую дату начала, название от трёх символов, место/адрес, отсутствие отмены, переноса и дубля. Отклонение проверяет актуальность версии и статус pending. Категория меняется только у успешно опубликованных выбранных записей.

Действия «всі за фільтром» подтверждаются с количеством очереди и выполняются порциями по 100 на стороне базы. Город и источник сохраняются во всех вызовах. Курсор по UUID исключает смещение страниц при публикации; серверный снимок времени исключает новые записи и пропускает изменённые после начала операции. Фильтр использует сохранённые категории, черновики на странице не применяет. Действия не являются одной общей транзакцией: при сетевой ошибке завершённые порции сохраняются, показаны их счётчики и сообщение об ошибке; очередь обновляется.

После включения автопубликации кнопкой строки, массовым действием или сохранением существующего источника предлагается обработать уже собранные pending тем же RPC. Отказ оставляет флаг включённым и очередь без изменений. Для нового источника собранных записей ещё нет.

Очередь показывает общее количество по фильтру, номер страницы и размер 25/50/100. После обработки пустой последней страницы номер корректируется. Пропущенные pending остаются с актуальными данными; уже опубликованные другим администратором записи закономерно уходят из очереди.

Проверка: локальная сборка и тесты с подменой RPC, включая частичный результат, весь фильтр, курсоры, ошибку следующей порции, размер страницы и отсутствующий SQL. SQL проверен статически; выполнение PostgreSQL и права доступа нужно проверить после ручного применения. Никаких GitHub pull/push и запросов к базе не выполнялось.
