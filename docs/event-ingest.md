# Сбор внешних событий с обязательной модерацией

Каркас работает отдельно от пользовательских `events`: публикация внешнего события не создаёт организатора, участие или чат. Данные `tow_leads` и `svoya_*` не затрагиваются.

## SQL

Для ручного выполнения: **`docs/sql/event-ingest.sql`**. Это точная копия `supabase/migrations/20261116090000_event_ingest.sql`.

Предварительно должна быть применена существующая `20261027085654_poruch_admin_console.sql`: используется её проверка администратора `poruch_private.is_admin()`. Новая миграция добавляет:

- `event_sources`: тип, URL, город, категория, включение, партнёрские параметры, резервное поле автопубликации, время и результат запуска, последние и суммарные счётчики.
- `ingested_events`: факты о событии, статус, контрольные суммы, ограниченные исходные данные, идентификаторы всех источников и отметки модерации.
- RLS и явные права: источники видит и изменяет только администратор; очередь видит только администратор, решения принимаются через защищённый RPC. Сборщик имеет отдельные RPC только для `service_role`.
- Публичный RPC `poruch_ingest_feed`: выдаёт только разрешённую проекцию будущих `approved`, без raw JSON, внутренних идентификаторов источников, токена запуска и настроек. `pending`, `rejected`, `expired`, отменённые и отложенные события не выдаются.

SQL подготовлен, **не применялся**. Локальный Supabase CLI отсутствовал в offline npm cache, поэтому файл подготовлен вручную с временной меткой после миграции админки. Проверка на реальном PostgreSQL/RLS остаётся после ручного применения.

## Источники и админка

В `/admin` сохранены существующие разделы в «Платформа», рядом добавлены:

1. **«Джерела»**: добавить/редактировать источник, выбрать тип и категорию, указать город и URL, включить/выключить, задать партнёрскую query-строку, увидеть результат и счётчики.
2. **«Афіша на модерації»**: очередь `pending`, название/дата/место/город/источник/ссылка, фильтры города и источника, поэлементное и массовое решение, пагинация по 25.

При публикации проверяется fingerprint показанной версии. Если сборщик успел изменить событие, решение отклоняется целиком и нужно обновить список. Отменённые, отложенные и прошедшие события публиковать нельзя.

Город источника — свободное текстовое поле, подсказки берутся из существующего каталога. Можно настроить источники для **любого города Украины**, например Ніжина: в сборщике нет списка из 24 разрешённых городов. Текущий пользовательский переключатель `DiscoveryCityContext` сохраняет свой существующий набор городов; расширение справочника всех населённых пунктов и автоматический поиск сайтов в эту задачу не входят. В ленте используется текущий выбранный город, категория, поиск и радиус для записей с координатами. Без координат события видны в городской ленте, но не имеют маркера на карте.

Рабочий адаптер сейчас — **`schema_org`**. `feed`, `telegram`, `manual` зарезервированы: включённый источник неподдерживаемого типа получает понятный результат `adapter_not_implemented`. Адаптеры добавляются через `scripts/ingest/adapters.mjs` и получают общий безопасный HTTP-клиент.

`auto_publish` существует и по умолчанию выключен, но **даже значение true не обходит модерацию**. В форме оно недоступно: обязательность ручного одобрения имеет приоритет.

## Что делает сборщик

- Честный User-Agent: `PoruchBot (+https://poruch.fun)`.
- Читает robots.txt перед страницей, учитывает группы PoruchBot, Allow/Disallow, наиболее длинное правило, `*`, `$` и Crawl-delay. Между HTTP-запросами минимум 2 секунды после предыдущего ответа, в том числе для robots и редиректов; больший Crawl-delay соблюдается. Неизвестный/недоступный robots — отказ от обхода; 404/410 разрешают обход. Запрещённая страница не запрашивается. Редирект страницы снова проходит проверку robots по новому адресу.
- Только публичные HTTPS-адреса, без URL credentials и нестандартных портов. DNS lookup привязывает запрос к проверенному публичному IP; локальные/private/link-local адреса отклоняются. Ограничены таймаут, размер ответа и число редиректов.
- Атомарный claim в БД допускает не более одного прохода источника за 24 часа, включая неудачную попытку и ручной перезапуск workflow. Сбой не вызывает автоматический повтор в тот же день. Токен запуска защищает от устаревшего работника.
- Разбирает JSON-LD в массивах, `@graph`, вложенных списках и ссылках `@id`; распознаёт Event и подтипы. Нормализует ISO даты в UTC, даты без смещения трактует в Europe/Kyiv; дата без времени означает начало указанного дня. Поля страны вне Украины исключаются, если страна явно указана. Координаты берутся только из разметки: геокодирование не запускается.
- Берёт название, время, место, адрес, координаты, цену «від», валюту и ссылки. Подтип задаёт категорию, иначе используется категория источника. Описание превращается в текст и ограничивается 200 символами **также в raw JSON**. Raw JSON содержит только ограниченный набор фактов, без HTML страницы, биографий и длинных текстов. Изображение не скачивается сборщиком; сохраняется лишь URL, который затем загружает браузер как обычную обложку.
- Канонический hash: нормализованные название + UTC время начала + место (или адрес) + город, независимо от источника. Уникальность в БД и сериализованное слияние препятствуют дублям между источниками. Идентификаторы и fingerprints отдельных источников сохраняются, чтобы неизменившаяся старая копия не отменяла уже найденное обновление.
- Изменившиеся факты возвращают событие в `pending`, очищая старое одобрение. При совпадении новой даты с уже существующей записью канонические записи объединяются. Отмена и перенос снимают событие с публичной выдачи до нового решения. Прошедшие записи становятся `expired`; при отсутствии endDate окончанием считается startDate. Исчезновение будущего события из страницы само по себе не считается отменой.

Нужен устойчивый `@id`/identifier источника. Запасной id строится из URL, названия и места без даты, поэтому перенос даты отслеживается. Если источник без стабильного id одновременно меняет название/место/URL, может потребоваться ручное сопоставление и отклонение старой записи. Нечёткое объединение похожих концертов намеренно не выполняется.

Адаптер читает **одну настроенную страницу за проход**. Рекурсивного обхода сайта, исполнения JavaScript, обхода защиты и автоматического поиска всех сайтов нет. Подойдёт страница с JSON-LD Event/списком событий; для сайтов только с клиентским рендерингом или ItemList без фактов понадобится отдельный адаптер.

## GitHub Actions

Добавить в Repository → Settings → Secrets and variables → Actions:

- **`SUPABASE_URL`** — URL нужного проекта.
- **`SUPABASE_SERVICE_ROLE_KEY`** — серверный service role key, никогда не `VITE_*`.

`.github/workflows/ingest.yml` запускается ежедневно в **04:17 UTC** и через **Run workflow**. Проверка отсутствующих секретов падает до установки зависимостей. Ключ доступен только проверке наличия и шагу сборщика, не передаётся установке npm или сборке сайта. В логи идут только UUID источника, счётчики и ограниченные коды результата; URL, тела ответов, ключи и сообщения SDK не выводятся. Ошибка хотя бы одного источника делает workflow красным, остальные источники обрабатываются.

После ручного применения SQL сначала добавить выключенный источник, проверить discover, затем включить. Workflow не добавляет сайты самостоятельно и не публикует события автоматически. Фактические источники в этот коммит не включены.

## Discover без Supabase и секретов

```powershell
node scripts/ingest/discover.mjs https://example.org/events https://another.example.org/afisha
```

Вывод — JSON для каждого URL: `allowed`, `eventMarkup`, количество объектов разметки `markupEvents`, количество валидных нормализованных `events`, код причины. Если robots проверить не удалось, `allowed: null`. Утилита ходит только к заданным сайтам и их robots/редиректам; к Supabase не подключается. Для одного URL без JSON-LD, но с клиентским рендерингом результат 0 ожидаем.

Для авторизованного серверного запуска вне Actions: задать `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` в окружении и выполнить `node scripts/ingest/run.mjs`. Не добавлять ключ в репозиторий и не запускать сборщик из браузера.

## Проверки и ограничения проверки

`npm test`: **76/76** проходят. `npm run build`: успешно. Локальная проверка в Edge на **360 и 1440px** подтвердила внешние карточки, партнёрские ссылки, отсутствие кнопок участия и сохранение мобильной высоты **236px**. Скриншоты: `qa-artifacts/onboarding-local/ingested-events-360.png` и `ingested-events-1440.png` (локальные артефакты, игнорируются Git). Все внешние запросы в браузерной проверке перехватывались/блокировались.

Тесты используют HTML-фикстуры, поддельный HTTP transport/часы и моки Supabase: JSON-LD, подтипы, даты/DST, ограничение raw/описаний, дедуп hash и переносы, robots, задержки, редиректы, отказ при недоступном robots, приватные IP, discover, завершение ошибочных запусков, отсутствие секретов, фильтры/массовая модерация, конфликт версии, управление источником, партнёрские ссылки, отсутствие join/chat и гонка A→B→A во внешней ленте. SQL-копии и ключевые ограничения проверяются статически.

Реальный сбор, workflow, подключение к Supabase и применение миграции не выполнялись. После ручного SQL проверить матрицу anon/non-admin/admin/service_role, повторный claim в пределах 24 часов, слияние дублей между двумя источниками, обновление approved → pending и конкурирующее решение модератора.

Нормы реализации: [robots RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html), [структурированные события и отмены](https://developers.google.com/search/docs/appearance/structured-data/event), [Supabase Database Functions](https://supabase.com/docs/guides/database/functions).
