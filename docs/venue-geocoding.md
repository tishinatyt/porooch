# Внешние события на карте и backfill

## Причина

Read-only проверка `https://chernihiv.karabas.com/concerts/` 16 ноября 2026 дала **17 нормализованных событий, 0 с координатами**. В JSON-LD есть залы и адреса, например театр на пр-те Миру, 23 и Палац культури на вул. Івана Мазепи, 23, но нет `geo`. Сборщик раньше сохранял только geo из источника; `DiscoveryMap` правильно исключала записи без пары координат. База для диагностики не использовалась.

Дополнительно карта получала только первую порцию внешней ленты. Теперь режим карты загружает все страницы одобренных событий выбранного города, категории и поиска, а лента сохраняет прежнюю подгрузку. Радиус применяется к известным координатам; событие без координат остаётся в городской ленте. Счётчик карты учитывает только записи с координатами.

## Геокодирование

`scripts/ingest/geocode.mjs` использует Nominatim Search с User-Agent `PoruchBot (+https://poruch.fun)`, `countrycodes=ua` и украинским языком. Первый запрос: «название места, адрес, город, Україна». Если подходящего результата нет — один запрос только с адресом и городом. Дублирование города в адресе убирается. Центроиды городов/регионов, неверные координаты и результаты вне UA не принимаются; выдуманных координат центра города нет.

Публичный Nominatim ограничивает регулярные скрипты **4 запросами в минуту**, поэтому пауза по умолчанию **15 секунд после ответа**, последовательно в одном процессе. Это строже общего максимума 1 запрос/с. После 403/429 новые запросы в этом запуске прекращаются. По умолчанию бюджет — **200 HTTP-запросов за запуск**; после его исчерпания события сохраняются без координат. `GEOCODE_MAX_REQUESTS=0` отключает новые HTTP-запросы, сохраняя использование кеша.

Результаты кешируются по нормализованным адресу и городу; если адреса нет — по названию и городу. Другие названия того же здания с тем же адресом используют один результат. Координаты из JSON-LD и уже записанных событий используются без HTTP. Одновременные обращения к одному месту используют один Promise.

**SQL для ручного выполнения:** `docs/sql/venue-geocode-cache.sql`, точная копия `supabase/migrations/20261116120000_venue_geocode_cache.sql`. Таблица содержит ключ, запрос, место/адрес/город, координаты, результат и время; доступ только `service_role`, RLS включён. Чужие таблицы и пользовательские события не изменяются.

Таблица **не обязательна для запуска**: при её отсутствии работает `.cache/venue-geocodes.json`, а workflow восстанавливает/сохраняет этот файл через Actions cache, в том числе при частичном сбое. Положительные результаты и «не найдено» сохраняются; временные ошибки могут повторяться через час. Для намеренного повторного поиска ранее не найденного места нужно удалить соответствующую запись из постоянного и файлового кеша. При потере Actions cache без SQL повторный поиск возможен; постоянная таблица предпочтительна.

Для регулярного большого каталога использовать собственный или подходящий внешний Nominatim endpoint: `NOMINATIM_URL=https://your-host/search`. В Actions это Repository Variable `NOMINATIM_URL`; бюджет — Variable `GEOCODE_MAX_REQUESTS`. У альтернативного endpoint минимальная пауза в коде всё равно не меньше секунды (по умолчанию остаётся 15 секунд). Не запускать публичный endpoint одновременно с нескольких машин/процессов: лимит относится ко всему приложению. Workflow объединяет collect/backfill одной concurrency-группой.

См. [политику публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/) и [Search API](https://nominatim.org/release-docs/5.0/api/Search/). Атрибуция OpenStreetMap сохранена на карте.

## Backfill

В GitHub Actions: **Collect events for moderation → Run workflow → mode: backfill**. Плановый запуск по-прежнему использует `collect`. Нужны прежние Secrets `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`.

Локально, когда серверные переменные уже заданы в окружении:

```powershell
node scripts/ingest/run.mjs --mode=backfill
```

Либо `INGEST_MODE=backfill`. В этом режиме **страницы источников, robots.txt и адаптеры не вызываются**. Читаются только `pending`/`approved` с отсутствующей парой координат, затем записываются только latitude/longitude. Одобрение, fingerprint и факты источника не меняются. Проверка fingerprint + места/адреса/города защищает от изменения события во время запроса. Уже заполненная пара не перезаписывается.

Пагинация идёт по последнему UUID, чтобы не пропускать строки, исчезающие из выборки после обновления. В логах — scanned/updated/missing, без ключей и адресов. Если бюджет закончился, можно повторить backfill: кеш и уже заполненные строки не расходуют запросы. После завершения обновить страницу/переключить карту, чтобы получить свежую выдачу.

Обычный collect тоже дополняет координаты; повтор неизменившихся фактов не мешает заполнению ранее пустой пары. Неудачный поиск не мешает сохранить событие в ленте. В очереди модерации есть пометка **«без координат»**.

## Карта и карточки

- Источники: фиолетовый маркер-билет; пользовательские события: синий круг. Совпадающие места объединены, количество видно на маркере. Для смешанной группы — двухцветный маркер.
- Одно место открывается списком событий, отсортированных по времени. Группируются одинаковые точки и одинаковый адрес/город с небольшим расхождением координат. В списке — обложка с прежним правилом согласия источника и запасной категорией, дата, адрес, источник, цена и «Купити квиток». У пользовательского события сохраняется переход в детали.
- Popup рендерится React portal, поэтому ошибка загрузки афиши корректно включает CategoryPlaceholder. Открытие popup не создаёт отдельные React roots. Масштаб вынесен вниз, чтобы не перекрывать заголовок.
- CSS Leaflet теперь поставляется локально с ленивым модулем карты. Внешняя загрузка CSS/иконок unpkg карте больше не нужна; тайлы остаются OpenStreetMap.
- Цена: `від 590 грн`. Дата в карточке и popup: `ср, 18 лист., 20:00` по Europe/Kyiv. Числовой формат в модерации сохранён.

Проверяются цена/дата, группировка места и все страницы карты.

Локальный Edge, **360 и 1440px**: два внешних маркера мест, отдельный пользовательский, два события в общем popup с афишами/билетными ссылками, запись со второй RPC-страницы. Скриншоты: `qa-artifacts/onboarding-local/ingested-map-360.png`, `ingested-map-1440.png`; результат — `ingest-result.json`. Тайлы и внешние запросы в браузерной проверке блокировались/подменялись.

Реальный Nominatim, backfill и workflow не запускались; к БД не подключались, SQL не применялся. Выполнено только чтение публичного Karabas для проверки исходной причины. Pull/push не выполнялись.
