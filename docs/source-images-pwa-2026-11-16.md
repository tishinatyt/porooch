# Обложки источников и обновление PWA

## Обложки

- Внешние события по умолчанию используют существующие иллюстрации `CategoryPlaceholder`. В проекте есть все категории; неизвестная получает оформление `other`. Новые изображения не потребовались. Размер контейнера обложки и высота карточек сохранены.
- Добавлен `event_sources.use_source_images boolean not null default false`. В форме источника — «Показувати афіші джерела (лише за згодою джерела)». Включение разрешает использовать URL афиши; отсутствие URL или ошибка загрузки возвращают иллюстрацию категории через существующий `EventMedia`.
- Публичная выдача учитывает флаг и не возвращает `cover_url` при выключенном флаге. Клиент дополнительно проверяет явное `true`; отсутствие поля в старом RPC означает `false`.
- Очередь модерации использует те же правила и показывает миниатюру 64×64.
- До применения SQL источники продолжают читаться через `select('*')`; миниатюры и лента используют категории. При сохранении с выключенным флагом код распознаёт отсутствие новой колонки и повторяет запрос без неё. Включение без SQL даёт понятное сообщение и не теряется молча. Ошибки сети не вызывают повторную вставку.
- Сборщик уже сохранял JSON-LD `image` в `cover_url`. Дополнительно поддержаны ссылки на `ImageObject` в `@graph`, поиск первого валидного URL в массиве и пропуск null/небезопасных значений. Файлы сборщик не скачивает.

**SQL для ручного выполнения:** `docs/sql/event-sources-images.sql`, точная копия `supabase/migrations/20261116100000_event_sources_images.sql`. Выполнять после миграции сбора событий `20261116090000_event_ingest.sql`. Файл добавляет колонку и обновляет прежнюю публичную проекцию RPC; RLS и пользовательские события не меняются. SQL не применялся, подключений к БД не было.

## Причина задержки PWA по коду и заголовкам

`autoUpdate`, `skipWaiting` и `clientsClaim` уже присутствовали. При этом `index.html` входил в precache и навигации обслуживались cache-first через стандартный `navigateFallback`. Открытая вкладка проверяла worker раз в час; отдельной проверки при возвращении в приложение не было. Это позволяло старой оболочке сохраняться до обнаружения обновления.

16 ноября 2026, 12:46 UTC, read-only HEAD к `https://poruch.fun/index.html` и `https://poruch.fun/sw.js` вернул для обоих **`Cache-Control: max-age=600`**, сервер GitHub Pages. Это HTTP-кеш на 10 минут, не бесконечный, но он также мог задерживать получение свежих файлов. Серверные заголовки GitHub Pages из статического репозитория не изменялись; решение не полагается на их немедленную ревалидацию.

## Что изменено в PWA

- Сохранены `skipWaiting`, `clientsClaim`, очистка старых precache и режим `autoUpdate` генератора.
- HTML исключён из precache. Маленький импортируемый скрипт worker загружает HTML по сети с `cache: 'no-store'` и `index.html?__poruch_build=<версия>`. Запасная HTML-копия используется только при ошибке сети. Для SPA-маршрутов берётся та же оболочка без изменения адреса страницы. Перед активацией worker проверяет доступность HTML новой сборки.
- Vite создаёт идентификатор сборки, `version.json` и метатег `poruch-build`. Worker отвечает этим же идентификатором через MessageChannel.
- Нативная регистрация использует `/sw.js?version=<версия>` и `updateViaCache: 'none'`, включая импортируемые скрипты. `sw.js` и `version.json` не перехватываются кешем навигаций и не входят в precache. Проверка `version.json` с уникальным query и `no-store` обходит старый HTTP/CDN cache key.
- Проверки запускаются при старте, раз в минуту в видимом приложении, при возвращении во вкладку и восстановлении сети. На недоступной сети сохраняется обычный механизм `registration.update()`.
- При смене контроллера или несовпадении версий worker/страницы выполняется одна перезагрузка. Защита хранится в sessionStorage и history.state; она работает и когда sessionStorage переполнен или запрещён. Первая установка совпадающей версии не перезагружает страницу. Повтор того же события не вызывает цикл даже при старом HTML. Отдельный обработчик автоперезагрузки `virtual:pwa-register` больше не используется, чтобы не было двух конкурирующих слушателей.

Уже открытая вкладка со старым JavaScript сначала использует прежний алгоритм обнаружения обновлений. Новый минутный цикл начинает работать после получения этой версии. Невозможно изменить выполняющийся старый JavaScript одним локальным коммитом без доставки обновления браузеру.

- `npm test`: **83/83**; `npm run build`: успешно.
- Моки покрывают флаг и старую схему, успешную/неудачную загрузку постера, миниатюры модерации и JSON-LD ImageObject.
- Локальный Edge **157.0.4341.60**, 360 и 1440px: без согласия запрос к постеру не отправлен; с согласием показан постер; 404 заменён иллюстрацией категории. Все три мобильные карточки имеют высоту **236px**. Скриншоты: `qa-artifacts/onboarding-local/ingested-events-360.png`, `ingested-events-1440.png`.
- `qa/check-pwa-local.mjs` собирает две настоящие production-версии и обслуживает их на одном локальном origin. Сервер намеренно оставляет старые unversioned HTML и sw.js в HTTP-кеше с `max-age=600`. Результат: первая установка — **0** перезагрузок, обновление A→B — **1**, повторные проверки — **0**, офлайн после обновления — **версия B**. Результат в `qa-artifacts/pwa-local/result.json`; внешние запросы в браузерных проверках блокируются.
- Проверки HTTP-заголовков были только чтением. Реальные изображения источников, новая схема в Supabase, новый production-деплой и физический Safari/iPhone не проверялись. Pull/push и применение миграций не выполнялись.

Запуск локальных браузерных проверок при установленном Playwright:

```powershell
$env:PLAYWRIGHT_MODULE='путь/к/playwright/index.mjs'
node qa/check-pwa-local.mjs
$env:CHECK_INGEST_ONLY='1'
node qa/check-onboarding-local.mjs
```

Справка по используемым механизмам: [MDN updateViaCache](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register), [Vite PWA periodic updates](https://vite-pwa-org.netlify.app/guide/periodic-sw-updates).
