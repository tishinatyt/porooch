# Одинаковые карточки и начало лент — 2026-11-15

## Причины и исправления

1. **Разная высота.** Предыдущий compact CSS явно задавал `height: auto`, снимал line-clamp и разрешал неограниченные переносы. Demo-метка, имя организатора и footer также добавляли разное число строк. Теперь на Home до 639px карточки афиши имеют высоту **236px**, личных событий — **296px**. В пределах каждой ленты ширина и высота всех карточек одинаковы. Блок деталей — **108px**: заголовок **36px / 2 строки**, описание **28px / 2 строки**, далее компактные дата/место. Пустое описание занимает тот же слот. Лишний текст обрезается line-clamp; полный текст доступен в деталях события. Обложки афиши всегда **56×56px**, 1:1, `object-fit: cover`, включая fallback без изображения.

   Для demo-метки зарезервирован постоянный слот. Имя и адрес ограничены по строке, footer — 50px. В мобильном footer оставлены счётчик участников, доступ и действия; мини-аватарки участников скрыты, чтобы их количество не меняло размер. Аватар организатора личного события остаётся. Все видимые кнопки карточек сохраняют минимум 44×44px. Поле description уже существовало в схеме, но не попадало в карточки: теперь оно читается вместе с имеющимися метаданными событий, без миграций и записей в базу.

2. **Направление.** `row-reverse`, RTL и `.reverse()` в пути этих лент не обнаружены: массив уже шёл в обычном порядке. Исправлять данные обратной сортировкой было бы неверно. Явно закреплены `dir="ltr"` и `flex-direction: row`. Первая карточка слева; touch-жест справа налево увеличивает scrollLeft и открывает следующую карточку. Проверено одинаково для афиши и знакомств.

3. **Открывалась вторая/demo-карточка.** До завершения загрузки Home показывает demo fallback. Реальные карточки вставляются перед тем же demo DOM-элементом, а native scroll-snap сохраняет ранее выбранный элемент. Раньше не было сброса при переходе от fallback к первой авторитетной загрузке. Добавлен `resetKey` pending→loaded и `useLayoutEffect`: временно отключается snap, scrollLeft/scrollTop устанавливаются в ноль, на следующем кадре snap возвращается. Отключён scroll anchoring, scroll-padding-inline стал 0. Смена категории/города/поиска/радиуса переоткрывает соответствующую ленту с первой карточки. Добавление страниц и same-scope realtime обновления позицию не сбрасывают.

## Проверки

- **52/52** unit/integration теста, `npm run build` (TypeScript, Vite, PWA), `git diff --check` и синтаксис QA — успешно.
- Новые unit tests моделируют demo→server prepend, проверяют прямой порядок/LTR, сброс после смены набора и сохранение позиции при append. Проверка карточек подтверждает наличие описания и работу перехода в детали.
- Локальный Edge: **360×800, 390×844, 430×932, 1440×900**. Внешние запросы блокируются, OAuth/data — только fixtures. Нет pull/push, подключений к базе или live smoke.
- В fixtures смешаны короткие/длинные заголовки, короткие/длинные/пустые описания, реальные обложки/fallback и demo-метки. Проверены одинаковые размеры всех отрисованных карточек обеих лент и постоянные слоты текста.
- После первой загрузки с задержкой, reload и смены категории scrollLeft=0; первая карточка полностью помещается в rail, край следующей виден справа. В QA нет ручного `scrollTo(0)` перед проверкой — проверяется поведение приложения.
- Touch-свайп справа налево должен открыть как минимум следующую карточку. Независимые end-scroll загрузки порций, категории/поиск, sticky, пустые состояния и кнопка создания также проходят.
- На мобильном начало карточек афиши — около **207px**, знакомств — **548px**, поэтому начало второй ленты остаётся в первом экране. Desktop сохраняет прежние размеры карточек/обложек и независимые колонки; новые ограничения высоты действуют только до 639px.
