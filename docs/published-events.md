# Сеансы и опубликованные внешние события — 17.11.2026

## Группировка показа

Внешние события группируются только в интерфейсе по нормализованным названию, месту и городу. Даты остаются отдельными записями в базе. Личные и другие события пользователей не группируются. Строки без известного места не объединяются наугад.

Карточка показывает ближайший будущий сеанс. Кнопка «ще N дат» в существующем футере открывает диалог: каждая дата имеет собственную ссылку на билеты, включая партнёрские параметры именно её источника. Мини-карточка на карте сразу содержит тот же список. Кнопка занимает место прежней CTA, размеры карточки и обложки сохранены, область нажатия минимум 44px.

Прошедшие даты, отменённые и отложенные события исключаются. Таймер по ближайшему началу и обновление при focus/visibilitychange переводят группу на следующую дату без перезагрузки. Идентификатор группы остаётся стабильным. Все страницы внешней ленты для выбранных города/категории/поиска загружаются порциями по 100: иначе дальние даты могли бы пропасть за границей страницы. Число видимых групп по-прежнему увеличивается кнопкой/прокруткой. Это увеличивает объём первоначальной загрузки данных для крупных городов; картинки и видео не загружаются этим запросом.

## «Опубліковані»

Раздел рядом с модерацией показывает отдельные опубликованные записи, включая каждый сеанс: миниатюра с правилами согласия источника, название, дата, место, город, источник и категория. Фильтры: город, источник, категория, буквальный поиск подстроки названия. Пагинация 25/50/100, общее количество count:exact.

По одному, выбранным и всему фильтру доступны снятие с публикации, навсегда скрыть и смена категории. Для выбранных проверяется updated_at, для фильтра — снимок времени и UUID-курсор порциями до 100. Изменившиеся записи пропускаются, завершённые порции сохраняются, показывается суммарный результат. Действия по всему фильтру и скрытие требуют подтверждения с количеством. При частичной сетевой ошибке сохраняется уже показанный итог и выводится реальный message базы.

«Зняти з публікації» возвращает запись в pending; это временная операция, и включённая автопубликация источника может снова опубликовать подходящую запись при сборе. «Приховати назавжди» устанавливает rejected + raw_data.moderation_reason=hidden и сохраняет закрытые от клиента ключи запрета: source aliases и нормализованная идентичность конкретного времени события. Поэтому изменение fingerprint/названия у того же внешнего id, новый источник того же сеанса или удаление прежней строки при дедупликации не возвращают её в очередь. Другие даты остаются независимыми. Сборщик проверяет запрет до старой логики записи; триггер также сохраняет rejected при INSERT/UPDATE, включая прямые обновления. Сквозного UI восстановления навсегда скрытых событий нет.

Вручную применить **[sql/published-events.sql](sql/published-events.sql)** после ingest-queue-repair.sql. Идентичная миграция: `20261117150000_published_events.sql`. Все тела используют `$fn$`; файл изменён редактором, без PowerShell-строк с SQL. SQL повторяемый, новые RPC разрешены только администраторам. Закрытая таблица запретов имеет RLS без клиентских прав. Чужие таблицы не затронуты.

Локальные проверки покрывают группировку и переход ближайшей даты, разные места/города, сохранение личных событий и всех билетных ссылок, диалог и popup карты, фильтры/версии/массовые действия опубликованных, повторный сбор с ответом hidden без обходной записи и обогащения. SQL проверен статически и на парность тегов.
